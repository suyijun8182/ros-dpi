# 社区主站部署

社区共享库由**社区主站**汇总：各 ROS-DPI 实例每 30 分钟心跳一次，每 6 小时附带一份匿名投票（远端 IP / 域名 → 应用），主站按来源网络计票，至少 2 个不同网络的实例一致才发布，再由各实例拉回去用。主站和普通实例是同一个镜像，只是设了 `SHARE_HUB=true`。

## 实例需要什么网络条件

- **实例不需要公网 IP**：心跳、上报、拉库都是实例主动连主站，和访问网页一样。
- **主站必须让所有实例都连得上**。只有 IPv6 地址的主站（家宽常见），Docker 默认网桥里的实例连不上（容器没有 IPv6 出口）。所以推荐把主站放在**有公网 IPv4 的 VPS** 上；VPS 也有 IPv6 的话再加 AAAA 记录，两种实例都能连。

## 在 VPS 上部署（推荐）

需要：一台有公网 IPv4 的 VPS（1 核 512MB 足够）、一个域名、Docker。

1. 域名解析到 VPS（A 记录；有 IPv6 再加 AAAA），安全组 / 防火墙放行 TCP 80 和 443。
2. 把仓库里的 [`deploy/hub/`](../deploy/hub/) 目录复制到 VPS，例如 `/opt/ros-dpi-hub`，然后：

   ```bash
   cd /opt/ros-dpi-hub
   cp .env.example .env      # 填 HUB_DOMAIN 和 ADMIN_PASSWORD
   docker compose up -d
   ```

3. 验证：`curl https://<你的域名>/api/share/v1/stats` 返回 `{"total":…,"online":…,"offline":…}`。
4. 各实例：系统设置 → 外部数据源 → 社区共享库 → **社区主站地址** 填 `https://<你的域名>`，保存后立即重新注册并同步；状态显示“已连接”即可。也可以用环境变量 `SHARE_HUB_URL`（网页填写的优先）。

**安全**：

- Caddy 自动申请并续期 HTTPS 证书，实例默认校验证书。
- 公网只开放 `/api/share/v1/*`（注册、上报、社区库、部署量），其它路径一律不转发；管理页面只绑在 VPS 本机的 `127.0.0.1:8080`，需要时用 SSH 隧道打开：`ssh -L 8080:127.0.0.1:8080 <VPS>`，然后在自己电脑上访问 `http://127.0.0.1:8080`。
- 主站不保存来源 IP，只存来源网络（IPv4 /24、IPv6 /56）的加盐哈希；每个实例有主站发的令牌，别人无法冒充；同一网络每天限注册 5 个实例，投票每小时最多收一次，请求体限 8MB。
- 主站管理页面的 系统设置 → 外部数据源 会显示“来源网络”数：实例很多却只有 1 个网络，说明前面的反向代理没有传客户端 IP（Caddy 默认会传）。

## 用自己的反向代理（Lucky / Nginx）

主站放在家里、前面已有 Lucky 或 Nginx 时：把 `https://<域名>/api/share/v1/` 转发到主站实例的 8080 端口，并确认转发时带上 `X-Forwarded-For`（Lucky、Nginx 的 `proxy_add_x_forwarded_for`、Caddy 默认都会带）。主站实例只信任来自内网地址的反向代理传来的这个头。

## 实例连不上主站时

设置页会显示原因。常见的是“本机没有 IPv6 出口”（主站只有 IPv6），三选一：

1. 主站改到有 IPv4 的 VPS（见上）；
2. Docker 实例开启 IPv6：Docker 27+ 取消 `docker-compose.yml` 末尾 3 行注释；或改用 Linux 一键安装（主机网络）；
3. 在实例所在内网、有 IPv6 的反向代理（如 Lucky）上加一条：监听一个内网 HTTP 端口 → 目标 `https://<主站域名>`（Host 头设为主站域名），再把实例的社区主站地址填成这个内网地址。
